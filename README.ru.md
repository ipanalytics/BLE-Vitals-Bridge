## Обзор

BLE-Vitals-Bridge объединяет измерения жизненных показателей с нескольких устройств Bluetooth Low Energy в единое локальное хранилище. Пакет читает тонометры, весы и сенсоры глюкозы через стандартные службы Bluetooth, разбирает кадры по спецификации ISO/IEEE 11073 и поддерживает дедуплицированную базу данных SQLite с настраиваемыми правилами сторожа.

## Архитектура

Поток данных следует такой последовательности:
1. **Ввод**: устройства BLE или импорт JSONL
2. **Разбор кадров**: обработка SFLOAT по стандарту ISO 11073 и определение единиц
3. **Нормализация**: преобразование единиц (кг/фунты, мм рт.ст., мг/дл)
4. **Дедупликация**: удаление повторных измерений по ключу
5. **Хранение**: база данных SQLite с ограничениями первичного ключа
6. **Сторож**: мониторинг частоты и обнаружение тишины
7. **Экспорт**: вывод CSV и отчеты о состоянии

## Формат данных

### Метрики и поля

| Тип метрики | Единицы | Ключ дедупликации | Примечания |
|-------------|---------|-------------------|------------|
| `weight` | кг | `source|metric|taken_at|value` | Флаг imperial сохраняется в исходном кадре |
| `systolic` | мм рт.ст. | `source|metric|taken_at|value` | Разбор значений SFLOAT |
| `diastolic` | мм рт.ст. | `source|metric|taken_at|value` | Разбор значений SFLOAT |
| `pulse` | уд/мин | `source|metric|taken_at|value` | Из кадров давления или глюкозы |
| `glucose` | мг/дл | `source|metric|taken_at|value` | Значения непрерывного сенсора |

### Схема базы данных

| Столбец | Описание |
|---------|----------|
| `dedupe_key` | Первичный ключ: `source|metric|taken_at|value` |
| `metric`, `value`, `unit` | Исходное измерение в оригинальных единицах |
| `taken_at` | Время с прибора, нормализованное к местному времени |
| `source`, `device` | Идентификатор источника и адрес устройства |
| `group_id` | Связывает связанные метрики (систола/диастола/пульс) |
| `raw` | Полный разобранный кадр в формате JSON |

## Возможности

- **Стандартные службы Bluetooth**: Поддержка Blood Pressure (`0x1810`), Weight Measurement (`0x2A9D`), Body Composition (`0x2A9C`)
- **Разбор SFLOAT**: Обработка значений IEEE 11073 SFLOAT с правильным извлечением мантиссы/порядка
- **Определение единиц**: Автоматическое преобразование imperial/metric на основе битовых флагов
- **Идемпотентные операции**: Команды импорта и прослушивания предотвращают дублирование
- **Обнаружение тишины**: Настраиваемый сторож отслеживает ожидаемые частоты измерений
- **Локальное хранение**: Одна база SQLite доступна на всех машинах
- **Интерфейс командной строки**: Инструменты командной строки для импорта, прослушивания, экспорта и статуса

## Быстрый старт

```sh
pip install "ble-vitals-bridge[ble]"    # Включает bleak для подключения BLE
bridge import ~/logs/scale.jsonl        # Безопасный импорт существующих логов JSONL
bridge watch cuff                       # Ожидание и сохранение одного измерения
bridge status                           # Показать последние readings и статус сторожа
bridge status --quiet                   # Код выхода 1 если источник молчит
bridge export --metric weight --days 90 > weight.csv
```

## Установка

Установите основной пакет с дополнительными компонентами для функциональности BLE:

```sh
pip install ble-vitals-bridge           # Только основная функциональность
pip install "ble-vitals-bridge[ble]"    # Добавляет подключение BLE через bleak
pip install "ble-vitals-bridge[dev]"    # Зависимости разработки (pytest, ruff)
```

Функциональность BLE требует соответствующих прав доступа к оборудованию Bluetooth в системе.

## Использование

### Команды

- `bridge watch <тип_устройства>`: Ожидание одного измерения с указанного устройства
- `bridge import <путь>`: Обработка файлов JSONL из предыдущих записей
- `bridge status`: Отчет о последних readings и состоянии сторожа
- `bridge export --metric <тип> --days <n>`: Экспорт данных CSV для анализа
- `bridge metrics`: Список доступных метрик в базе данных

### Коды выхода

- `0`: Успех, данные доступны или операция завершена нормально
- `1`: Ошибка во время выполнения операции
- `2`: Сторож обнаружил молчащий источник (при использовании `--quiet`)

## Результаты/Артефакты

- **База данных SQLite**: По умолчанию `vitals.db` с дедуплицированными измерениями
- **Экспорт CSV**: Форматированные данные для графиков, таблиц или медицинского анализа
- **Отчеты о состоянии**: Уведомления сторожа о пропущенных измерениях
- **Исходные кадры**: Полные представления JSON разобранных кадров устройств

## Конфигурация

Правила сторожа определены в `watchdog.DEFAULT_RULES` и связаны с типом метрики, а не с устройством. Ожидаемые значения по умолчанию:

| Метрика | Ожидаемая частота | Причина |
|---------|------------------|---------|
| `weight` | Каждые 14 дней | Минимум два взвешивания в месяц |
| `systolic` | Каждые 7 дней | Еженедельный контроль давления |
| `glucose` | Каждые 36 часов | Непрерывная работа сенсора |
| `pulse` | Каждые 36 часов | Совместно с readings глюкозы |

Правила настраиваются без изменения кода при замене устройств.

## Эксплуатационные замечания

Когда устройство прекращает передачу, сторож определяет это через анализ частоты. Система различает:

- **Молчание устройства**: Нет новых измерений в течение ожидаемого времени
- **Проблемы связи**: Временные проблемы связи BLE
- **Нормальные интервалы**: Ожидаемые интервалы на основе шаблонов использования устройства

Частоты измерений отслеживаются по типу метрики: вес (14-дневный цикл), давление (7 дней), глюкоза/пульс (36 часов непрерывно).

## Объем проекта

Этот пакет решает основную проблему консолидации измерений BLE без зависимости от поставщиков. Он обрабатывает технические сложности протоколов Bluetooth, сохраняя архитектуру с приоритетом локального хранения.

## Сценарии использования

- Персональная консолидация данных о здоровье с нескольких устройств BLE
- Локальное резервное копирование измерений до загрузки в облако поставщика
- Сбор данных для исследований с стандартизованными форматами
- Интеграция с личными панелями мониторинга здоровья
- Подготовка к медицинским консультациям с последовательными данными

## Ограничения

- **Зависимость от оборудования**: Требуется совместимое радио BLE и соответствующие права доступа системы
- **Вариации протокола**: Реализации Bluetooth различаются между производителями устройств
- **Требования к чтению в реальном времени**: Чтение BLE в реальном времени требует `bleak` и прав доступа к системе
- **Проприетарные протоколы**: Шифрованные или проприетарные протоколы (как Xiaomi MiBeacon) не поддерживаются
- **Соответствие стандарту службы**: Зависит от реализации устройствами стандартных служб Bluetooth

## Тестирование

Запустите полный набор тестов без требований к оборудованию:

```sh
pip install -e ".[dev]"
pytest -q               # 26 тестов, покрывающих все компоненты
ruff check .
```

Тесты включают двунаправленную конструкцию и проверку кадров, чтобы обеспечить точность парсера за пределами самосогласованности.
