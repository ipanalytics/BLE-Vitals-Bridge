# BLE-Vitals-Bridge

_English version: [README.md](README.md)_

**Три домашних прибора, один локальный файл — и сторож, который замечает, когда один из них замолчал.**

Тонометр, весы и сенсор глюкозы умеют одно и то же: отдать одно измерение по Bluetooth и
положить его в своё приложение. Три приложения, три облака, три разных представления о том,
который сейчас час, — и ни одно из них не скажет, что прибор не выходил на связь девять дней.
Здесь собрано то, что действительно трудно.

## Что он делает

- **Читает тонометр** через стандартную службу артериального давления (`0x1810`, измерение
  `0x2A35`) и разбирает кадр как ISO/IEEE 11073, а не как обычные целые числа.
- **Читает весы** через Weight Measurement (`0x2A9D`) и Body Composition (`0x2A9C`), включая
  кадры, которые приезжают в фунтах из-за одного бита в первом байте.
- **Забирает журналы, которые уже есть** — строки JSON от прежних скриптов, и делает это
  идемпотентно: повторный прогон ничего не меняет.
- **Держит один файл SQLite** с единственным первичным ключом `источник|метрика|момент|значение`.
  Одно измерение не может лечь дважды, каким бы путём оно ни пришло.
- **Следит за тишиной**: у каждой метрики есть ожидаемая частота, и `bridge status` превращает
  «ничего не пришло» в строку с числом.
- **Отдаёт CSV** для графика, таблицы или врача.

## Быстрый старт

```sh
pip install "ble-vitals-bridge[ble]"    # [ble] тянет bleak; разбор журналов работает и без него
bridge import ~/logs/scale.jsonl        # файлы прежних скриптов, повторять безопасно
bridge watch cuff                       # ждать один кадр и сохранить его
bridge status                           # что пришло, когда и чего не хватает
bridge status --quiet                   # для крона: выход 1, когда источник молчит, без вывода
bridge export --metric weight --days 90 > weight.csv
```

Ставится на машину с Bluetooth-радио. Хранилище — обычный файл, поэтому читать его может любая
машина.

## Четыре вещи, которые действительно трудны

**1. Кадр тонометра — не целые числа.** В `0x2A35` лежат 16-битные SFLOAT: 12-битная мантисса и
4-битный знаковый порядок. Прочитаешь их как `int` — и обычные 128/84 превращаются в 15616/10752,
что выглядит как сломанная манжета, а не как ошибка разбора. Парсер разбирает и мантиссу со
знаком, и отрицательные порядки; на оба случая есть тест.

**2. Один бит превращает килограммы в фунты.** В `0x2A9D` единица — 0,005 кг, но если выставлен
бит 0, весь кадр идёт в 0,01 фунта. Весы, которые «показывают шаг 0,01 кг», — это весы, у которых
бит 0 проигнорировали. В хранилище вес всегда в килограммах, а в исходном кадре остаётся флаг
`imperial`, чтобы выбор был виден.

**3. Повторные чтения и повторный импорт.** Одно и то же взвешивание приходит не один раз:
прибор повторил отправку, телефон прошёл рядом дважды, ты снова скормил вчерашний журнал. У
каждого измерения есть ключ `источник|метрика|момент|значение`, он же первичный ключ таблицы,
поэтому дубль просто не записывается. Повторный импорт того же файла честно отвечает
`0 новых измерений` и не трогает ни одной строки.

**4. Тишина.** У поломки моста нет сообщения об ошибке: измерения просто перестают приходить, и
снаружи всё выглядит нормально. `bridge status` сравнивает каждую метрику с её частотой:

| Метрика | Ожидаемая частота | Почему |
|---|---|---|
| `weight` | раз в 14 дней | взвешивание минимум дважды в месяц |
| `systolic` | раз в 7 дней | измерение давления раз в неделю |
| `glucose` | раз в 36 часов | сенсор непрерывный, тишина означает проблему |
| `pulse` | раз в 36 часов | приходит вместе с кадром глюкозы |

Частоты лежат в `watchdog.DEFAULT_RULES` и привязаны к метрике, а не к прибору: замена манжеты на
другую манжету не требует правки кода.

## Хранилище

Одна таблица, потому что вопросы простые (что последнее, какой тренд, когда источник писал в
последний раз):

| Столбец | Смысл |
|---|---|
| `dedupe_key` | первичный ключ: `источник\|метрика\|момент\|значение` |
| `metric`, `value`, `unit` | число в той единице, которую имел в виду прибор |
| `taken_at` | момент, записанный прибором, приведённый к местному времени без зоны |
| `source`, `device` | какой источник записал и с какого прибора |
| `group_id` | связывает части одного кадра (систола, диастола, среднее, пульс) |
| `raw` | разобранный кадр в JSON: на поздний вопрос можно ответить, не подходя к прибору |

## Тесты

```sh
pip install -e ".[dev]"
pytest -q        # 25 тестов, Bluetooth-железо не нужно
ruff check .
```

Фикстуры собирают кадры в обе стороны — тест упаковывает SFLOAT и читает его обратно, — поэтому
парсер, который согласен сам с собой, тест не пройдёт. Остальное (дубликаты, свежесть, счёт
импорта, выгрузка CSV) работает на временном файле SQLite.

## Чего здесь намеренно нет

- **Ни облака, ни учётной записи, ни приложения производителя.** Если прибор требует приложение —
  это повод прочитать стандартную службу, а не повод где-то регистрироваться.
- **Никакого извлечения ключей.** Весы Xiaomi, которые вещают шифрованным MiBeacon без ключа
  привязки, прочитать нельзя, и вытаскивать ключ из чужого приложения этот пакет не станет.
- **Ни дашборда, ни графиков.** Есть выгрузка CSV: читать числа должен человек, а медицинское
  суждение не место в мосте данных о здоровье.
- **Никаких молчаливых переводов единиц.** Всё хранится в том виде, в каком пришло; перевод в
  килограммы происходит один раз, в парсере, и виден в исходном кадре.
